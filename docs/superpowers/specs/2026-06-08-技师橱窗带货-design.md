# 技师橱窗带货 MVP 设计（成人用品 · 积分制 · 按国家分货）

> 内部代号 M09a · 2026-06-08 · 状态：设计待评审

## 1. 背景与定位

平台维护一个**按国家分货的成人用品供应库**。技师从「自己服务国家有货」的商品里选品，上架到自己的橱窗展示。客户通过某个技师的橱窗下单，用平台积分支付；平台负责发货履约（隐私包装），技师全程不碰库存/物流，订单送达后技师拿积分佣金。

一句话：**技师只负责把商品推荐给客户、促成下单，剩下的供应链由平台承担，成交后分成。**

这不是约会型功能，定位与 LoveRush「撮合线下真人服务抽佣」一致——橱窗是技师把流量变现的第二条腿，平台赚商品差价、技师赚佣金。

后端骨架已写好一大半，很可能像 M16 当初那样「代码全建、生产从没跑通」。已确认存在的部分：

**关键缺口（本设计要补的）**：
1. 商品**无国家维度字段**（`shop_items` 没有 `countryCodes`）— 用户核心诉求
2. **退款/缺货回滚函数完全不存在**（`status` 有 cancelled/refunded 枚举但无逻辑）
3. **分成是「下单即结佣即可提现」**，对实物商品+退款是风险
4. **无年龄(18+)门槛** — 成人用品法律红线
5. 无后台商品管理页、技师选品 UI、客户橱窗展示 UI（前端入口未知）

## 3. MVP 范围

### 做（业务闭环必需）
- 商品按国家分货（国家级颗粒度）
- 技师选品 → 橱窗展示 → 客户下单（积分支付）
- 后台手动履约（标记发货/送达）
- **年龄 18+ 门槛**
- **退款/缺货闭环 + 佣金后移到送达结算**
- 收货地址采集（复用现有加密字段）+ 隐私包装默认
- 跨境约束：MVP 只做「本国发本国」
- 客户端订单/通知隐私脱敏
- 下单/发货/送达状态通知

### 不做（YAGNI，留后续）
- 法币/第三方支付（顶部注释提到的 Stripe/Adyen 全部不做，纯积分）
- 物流 API 对接（纯后台手动）
- 复杂类目体系（`category` 文本够用）
- 技师自定义佣金率谈判（先固定平台默认 20%）
- 退货 RMA 自助流程（只做后台手动退款）
- 城市级分货颗粒度（先国家级）
- 中心化商城（**只能通过技师橱窗下单**，佣金归属清晰）

## 4. 数据模型改动（最小 diff，新迁移 0050+）

**`shop_items` 加 1 列**
```
country_codes text[]   -- 可售国家 ISO alpha-2，如 {TH,MY}；空数组=暂不可售
```
> 国家区分只需这一列。库存/图/定价/分成字段都已存在，不动。

**`shop_orders` 加 2 列 + 1 状态语义**
```
commission_status text default 'PENDING'  -- PENDING（已下单未结佣）/ SETTLED（已送达结佣）/ VOID（退款作废）
refunded_at timestamptz                    -- 退款时间
```
> `shippingAddressEncrypted`、履约时间戳、`status` 都已存在，复用。

**用户档案加 1 列（年龄门槛）**
```
users.adult_confirmed_at timestamptz   -- 首次确认成年的时间；NULL=未确认
```

## 5. 业务闭环（三方端到端动线 + 资金/结算时机）

```
【平台运营】后台「成人用品供应库」
  └─ 新建商品：标题/图/积分价/成本/佣金率/库存 + 勾选可售国家(country_codes) → 上架(is_active=1)
        │
【技师】橱窗管理页
  └─ 浏览「我服务国家(serviceCityId→cities.countryCode)有货」的商品
  └─ 选品上架 → 进 therapist_shop_listings → 我的橱窗
        │
【客户】技师主页/对话页 →「TA 的橱窗」→ 选商品 → 下单
  ├─ 首次：弹 18+ 成年确认 → 写 users.adult_confirmed_at
  ├─ 填收货地址（复用 outcall 地址采集，加密存 shippingAddressEncrypted）
  └─ 确认 → debit(SHOP_PURCHASE) 扣积分（余额不足跳充值）
        │   shop_orders: status=paid, commission_status=PENDING
        │   ⚠️ 佣金此刻【冻结不入账】（与现状不同）
        ↓
【平台运营】后台订单页
  ├─ 隐私包装 → 标记「已发货」(填 trackingNumber/备注) → status=shipped → 通知客户
  └─ 送达 → 标记「已送达」 → status=delivered
        │   ✅ 此刻才 credit(SHOP_COMMISSION) + 累计 therapistEarnings → commission_status=SETTLED
        ↓
【技师】佣金入 therapistEarnings 可提现  ←─ 闭环完成

异常分支：
  缺货/客户拒收/平台无法发货 → 后台「取消退款」
    → 退客户积分 credit(REFUND) → 回补 stockQty/soldCount
    → 若已 SETTLED 则扣回技师佣金(积分+cents 两账户)；PENDING 则直接作废
    → status=refunded, commission_status=VOID
```

### 关键改造：佣金结算时机后移
现状 `placeShopOrder()` 在下单时就 `credit` + 累计 `therapistEarnings`。本设计拆成两段：
- **下单**（`placeShopOrder`）：只扣客户积分、建单、扣库存，佣金记为 `PENDING`，**不 credit、不入 earnings**。
- **送达**（新增 `settleShopOrder`）：运营标记 delivered 时才执行原 `placeShopOrder:173-200` 的 credit + earnings 累计，置 `SETTLED`。

理由：实物可能缺货/退货，下单即结佣会导致退款时佣金已被技师提现，损失平台兜。

## 6. 国家维度机制（商品挂国家标签）

- 商品 `country_codes` 决定它在哪些国家可售。
- 技师服务国家：`therapists.serviceCityId → cities.countryCode`（复用 `resolveTz` 同款解析链路）。
- 技师选品页、客户橱窗展示都按 `current_country = ANY(shop_items.country_codes)` 过滤。
- 「某国完全没货」= 该国没有任何商品挂标签 → 橱窗自然为空，无需额外总开关。
- **本国发本国**：MVP 假设发货地=客户所在国，不做跨境。`country_codes` 同时表达「可售」与「可发」。

## 7. 第一档必需项详细设计

### 7.1 年龄 18+ 门槛
- 下单接口前置校验 `users.adult_confirmed_at`，为 NULL 则返回需确认的错误码。
- 前端首次进橱窗或下单时弹「我已年满 18 周岁」确认，确认后 PATCH 写入时间戳。
- MVP 不做证件验证（过重），只做自声明 + 留痕。

### 7.2 退款/缺货闭环（新增 `refundShopOrder`）
单一函数处理全部回滚，事务内：
1. 校验订单状态（paid/shipped/delivered 可退；已 refunded 幂等返回）
2. `credit(REFUND)` 退客户积分
3. 回补 `shop_items.stockQty += qty`、`soldCount -= qty`、listing `soldCount -= qty`
4. 若 `commission_status=SETTLED`：从技师扣回佣金——`debit` 积分账户 + `therapistEarnings.availableCents/shopCommissionCents -= commissionCents`（注意余额不足时记负债/告警，不静默吞）
5. 若 `commission_status=PENDING`：无需扣技师（本就没入账）
6. 置 `status=refunded, commission_status=VOID, refunded_at=now()`

### 7.3 佣金后移（见 §5 关键改造）
`settleShopOrder(orderId)` 由后台标记送达触发，幂等（重复调用不重复 credit，靠 `commission_status != PENDING` 短路 + idempotencyKey）。

## 8. 第二档轻量项

- **跨境约束**：MVP 锁「本国发本国」，下单时校验客户国家 ∈ 商品 `country_codes`，否则拒单。
- **隐私脱敏**：客户订单列表/通知用脱敏标题（复用通知 `obfuscate` 能力），不直接显示成人用品名；技师/客户端默认不在公开位置暴露商品名。
- **状态通知**：下单/发货/送达接 M19 通知。佣金 `credit` 时 `maybeNotifyWallet` 已自动发钱包通知；物流状态(shipped/delivered)需手动发 notification。

## 9. 边界与兜底（spec 记录，不单独决策）

- 技师未设 `serviceCityId` → 国家推不出 → 橱窗为空 + 引导补全服务城市。
- `shippingAddressEncrypted` 解密链路：确认加密用的密钥与解密入口（后台运营发货时需看明文地址）。**实现前必须验证此链路通，否则发不了货。**
- 平台下架商品（`is_active=0`）：技师橱窗里已上架的它隐藏，已下单的订单不受影响照常履约。
- 并发超卖：`stockQty` 检查与扣减非同一行锁，量小可接受；spec 标注，后续加 `SELECT ... FOR UPDATE` 或乐观锁。
