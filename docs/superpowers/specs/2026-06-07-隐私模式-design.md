# 隐私模式 完整需求设计(客户端 + 技师端)

> 2026-06-07 · 起因:隐私模式半成品,要做完整,技师端 + 客户端同时调整。
> 三路调研(当前代码 + 客户侧隐蔽标杆 + 服务者侧控曝光/IM 隐私标杆)后定。

## 1. 核心框架:隐私按角色分两件事

| 角色 | 隐私诉求 | 一句话 |
|---|---|---|
| **客户** | 隐蔽自己 | 别被熟人/配偶发现我在用这种服务、别暴露我的身份/行踪/账单 |
| **技师** | 控曝光 | 控制谁能看到我、真人信息别外泄、防盗图、上门别暴露精确位置 |

**现状最大错配:技师端没有专属隐私页,直接共用 `/me/privacy` 客户页**(PIN/计算器伪装这些对技师意义不大,技师真正要的"控曝光"一个都没有)。所以第一步是**拆成两套角色化隐私中心**。

## 2. 现状缺口图(调研 Explore 实测)

**客户侧 · 设备隐蔽(地基已不错)**
- ✅ 真能用:PIN 锁屏(防爆破)、自动锁回、通知内容模糊(obfuscateNotifications)、勿扰时段(quietHours)、拉黑(block_list)、消息软删
- ⚠️ 半成品:通知伪装显示名(有 UI 无后端+无 DB 列)、计算器伪装 decoy(有 DB 列无 UI)、紧急销毁 panicWipe(有 DB 列无 UI)、配偶兜底手势(纯 UI 占位)、银行扣款外显名(写死 "L&R Service",无开关无存储)
- ❌ 没有:隐藏客户自己的在线状态、隐身浏览、阅后即焚、注销即删数据承诺、账单中性名真配置

**技师侧 · 控曝光(几乎全空)**
- ✅ 有但分散:在线状态开关(t/home)、媒体可见性分级(media_assets.visibility)、社交联系积分解锁、AI 分身零标识、上门"确认后才给门牌"、拉黑
- ❌ 没有:技师专属隐私页、地区隐身(geo-block 本市/老家防熟人)、相册按亲密度/付费门控的统一入口、对未付费客户隐在线/last-seen、防盗图水印、防截图、骚扰静默限制、号码代理

## 3. 调研对标结论(可直接抄的标准)

- **客户侧"设备外显三件套"= 行业安全底线**(Grindr 把 App 图标伪装做成全员免费):App 图标伪装 + 通知不显内容 + PIN/生物锁。LoveRush 已有 PIN+通知模糊,缺图标伪装的 UI。
- **incognito「看人不被看 + 仅对我主动选中者可见」= 这一品类旗舰功能**(Tinder/Feeld/Grindr 三家收敛且都设付费墙)。
- **"注销即彻底删数据"是全行业失分点**(Mozilla 判 11 款陪伴 App 全 Privacy Not Included)→ 低成本高信任差异化。
- **账单中性商户名 = 成人支付标配**(Fansly 显示中性名;中性描述符降 30-50% 隐私争议)。
- **技师侧:地区隐身做城市/区级**(OnlyFans 整国屏蔽太粗,但有 VPN 绕过漏洞,话术要诚实"只防随便逛到的熟人")。
- **技师真人照防泄硬招 = 每客户唯一隐形水印(forensic watermark)+ DRM/防截图兜底**(Privly/Fansly),泄露可溯源到具体客户账号。
- **IM 隐私分级标准**(Telegram/Signal):在线/last-seen/已读/typing 三档(所有人/联系人/没人)+ 对称(藏别人也看不到别人)+ 自毁消息 + 截图告警(承认无法 100% 拦)。
- **上门地理隐私 = 确认门控(LoveRush 已领先)+ Uber 式双向号码代理(永不出真号)+ 行程态临时定位结束回收**。
- **AI 分身特有(标杆都没有)**:分身的在线/typing 可见性要服务"不露馅"——不能显示"永远在线",配合已有"不秒回+debounce"。

## 4. 落地分期(依赖序 · 价值优先 · 适配内部打磨阶段)

### P0 · 收尾 + 拆双端(低成本把已有做完整,先消除错配)
1. **隐私中心角色化拆分**:技师进 `/me/privacy` 看到的是技师版(控曝光),客户看客户版(隐蔽)。可同一路由按角色渲染不同分区,或技师走 `/t/me/privacy`。
2. **补"通知伪装显示名"后端**:privacySettings 加 `notificationDisguiseLabel` 列 + SettingsBody 透传 + 推送时用它替换标题(已有 obfuscate 逻辑,叠加替换名)。
3. **计算器伪装 decoy 补 UI**(DB 列已就绪)+ **紧急销毁 panicWipe 补 UI**(DB 列已就绪)。把"配偶兜底手势"并入 decoy(同一概念,别再单独占位)。
4. **银行外显名做成真配置**(privacySettings 加列 or 复用,前端可见但当前写死)。
5. **客户隐藏自己在线状态**(客户侧目前完全不能控)。

### P1 · 技师控曝光核心(技师侧从 0 到 1)
6. **技师隐私面板**:把分散的能力收纳成一页(在线状态、媒体可见性、社交解锁、拉黑)+ 新增:
7. **地区隐身(geo-block)**:技师选"对某城市/区隐身",该地区客户搜不到/推荐不到他;therapists 加 `geoBlockAreas` 字段,发现/推荐 query 过滤。
8. **在线/last-seen 对未付费客户隐身**:分级可见(所有人/已付费/没人),对称。
9. **骚扰静默限制(Restrict)+ 敏感词过滤**:把骚扰客户静默降级(不通知对方)+ DM 敏感词进隐藏区。

### P2 · 真人信息防泄硬功
10. **每客户唯一隐形水印**:技师真人照/撩拨图发出时按收图客户嵌唯一水印(覆盖 AI 分身代发),泄露可溯源。
11. **防截图 + 告警**:私聊真人照 Android FLAG_SECURE 硬阻断 + 截图告警(诚实:部分平台拦不全)。
12. **阅后即焚真人照**(view-once + 计时双端删),复用素材库范式。
13. **上门号码代理**(masked calling,Twilio/Voice Proxy 思路)叠加已有确认门控。

### P3 · 加分差异化
14. **incognito 隐身浏览**(客户:看技师不被记录/不进"看过我");15. **注销即彻底删数据**(可验证承诺);16. **Panic Button**(一键跳伪装页);17. **私钥逐人解锁真容**。

## 5. 边界 / 待决策
- **砍 or 留**:配偶三指手势伪装(高成本低频)→ 建议并入计算器 decoy,不单独做;紧急销毁 panicWipe → 留(DB 已有,补 UI 便宜)。
- 防截图/水印是工程硬骨头(P2),iOS/Android 行为不一致,话术要管理预期(标杆都承认拦不全)。
- AI 分身可见性"装真人"那层是本平台自研、标杆无,放 P1/P2 配合节奏引擎。

## 6. 验证
- P0/P1 每项:后端字段迁移 + API + 前端开关接通,e2e 断言落库 + 生效(如 geo-block 后该地区客户 query 不返回该技师)。
- 隐私是信任功能:每个"隐藏/删除"动作都要真生效(别做假开关),按 [[feedback_ux_first_design_standard]] 状态完整。
