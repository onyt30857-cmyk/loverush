# M06 分身回复语音化（30% 语音 / 70% 文字）· Design

- 日期：2026-06-09
- 模块：M06 技师 AI 分身（ai_alter）
- 目标：分身回复客户消息时，约 30% 用**技师本人复刻声音**的语音、70% 文字，增强真人感。
- 改动面：后端单点 `ai_alter.ts` + 一张技师端引导卡。**前端聊天页零改动**（语音气泡已就绪）。

---

## 1. 背景与现状（已核实生产 origin/main @9faee15）

声音复刻 + 语音消息的**全套地基已在生产**，本需求只是把现成能力接进分身的日常回复管线：

| 能力 | 现状 | 位置 |
|---|---|---|
| 声音复刻存储 | `therapists.eleven_voice_id`(ElevenLabs 真克隆)、`voice_intro_url`(样本) | `packages/db/src/schema/therapists.ts` |
| TTS 文字→语音 | `synthesizeWhisper(ctx,{therapistUserId,text,cloneOnly?})` → R2 公开 URL \| null | `apps/api/src/services/voice.ts:241` |
| 降级链 | ElevenLabs 真克隆 → OpenAI 通用女声 → null（`cloneOnly:true` 时跳过 OpenAI，无真克隆直接 null） | `voice.ts` |
| 语音消息入库样板 | `type:'voice'` + content=`JSON{text,audioUrl}` + `isAiAlter` | `apps/api/src/services/companion.ts:176-187` |
| 前端语音气泡 | `VoiceWhisperBubble`（HTML5 audio + 波形 + 转录），聊天页已按 `m.type==='voice'` 渲染 | `apps/web/components/chat/VoiceWhisperBubble.tsx`、`apps/web/app/conversations/[id]/page.tsx:910` |
| 技师端复刻入口 | `/t/me/ai-alter` 已嵌 `<VoiceCloneCard/>`（上传样本+试听+确认克隆） | `apps/web/app/t/me/ai-alter/page.tsx:166` |
| 分身回复主管线 | `maybeReplyAsAlter()`：redline@983 → finalText@988 → validateOutput@992 → `coalesceSegments(splitIntoSegments(finalText))`@1007 → sendMessage 循环@1034 | `apps/api/src/services/ai_alter.ts` |

**生产真实覆盖（2026-06-09 实测）**：67 个技师中仅 **1 个**（Mei，userId `65cd11d4-f3f2-455c-bc09-25b708abc3d4`）真克隆了声音。→ 覆盖率 1/67，**P0 必须带「催复刻」引导**，否则 99% 对话发不出语音。

---

## 2. 已拍板的产品决策

1. **先催复刻再开**：只有技师**真克隆完成**(`eleven_voice_id` 非空)才发语音。没克隆的保持纯文字。技术上用 `synthesizeWhisper(..., {cloneOnly:true})`——没真克隆返 null、**绝不降级 OpenAI 通用女声**。守住「声音必须是她本人」的露馅红线（[[feedback_ai_stealth]]）。
2. **偏短句触发**：长文本 / 含 URL / 含结构化卡片标记的回复强制走文字；其余正常对话里按 30% 抽语音。控成本（ElevenLabs 按字符计费）+ 更自然（真人语音多是短句）。
3. **P0 带引导卡**：对未复刻技师，在分身设置/工作台展示引导卡催其复刻。
4. **共存付费语音**：与 M18 付费「悄悄话语音」(`voice_whisper`) 独立共存——后者是客户付费触发的亲密动作，本功能是日常对话的免费真人感，触发路径不同、互不影响。

## 3. 核心设计

### 3.1 决策函数 `decideAlterVoice()`（新增，ai_alter.ts）

```
decideAlterVoice(ctx, {
  finalText: string,
  therapistUserId: string,
  rand?: () => number,   // 默认 Math.random，注入便于测试（同 coalesceSegments 范式）
}): Promise<boolean>
```

三道门，**全过才返回 true**（顺序按成本从低到高，先廉价判断再查库）：

1. **短句门**（纯函数，零 I/O）：以下任一命中 → false
   - 文本长度 > `VOICE_MAX_LEN`（默认 60，按「去空白后的字符数」算，中文友好）
   - 含 URL（正则 `/https?:\/\//i`）
   - 含结构化卡片/markdown 链接残留标记（防御性：`[`...`](`、`\n\n` 多段已被后续不分段处理，但仍排除明显非口语内容）
2. **真克隆门**（查库）：`select eleven_voice_id from therapists where user_id=?`，为空 → false。
3. **30% 抽签**：`rand() < VOICE_RATIO`（默认 0.3）。

`VOICE_MAX_LEN` / `VOICE_RATIO` 定义为模块常量（P1 可搬后台配置，见 §6）。

### 3.2 插入位置与发送逻辑（ai_alter.ts，maybeReplyAsAlter）

在 `validateOutput` 通过(@992) 之后、`coalesceSegments`(@1007) 之前插入：

```
const wantVoice = await decideAlterVoice(ctx, { finalText, therapistUserId });
let audioUrl: string | null = null;
if (wantVoice) {
  const { synthesizeWhisper } = await import('./voice');
  audioUrl = await synthesizeWhisper({ db: ctx.db }, {
    therapistUserId, text: finalText, cloneOnly: true,   // 只用真克隆
  }).catch(() => null);
}

if (audioUrl) {
  // —— 语音分支：不分段，整条作一条 voice 消息 ——
  // （可选）发送前复用现有 segmentDelayMs 给一个"录制中"的拟真延迟
  const s = await sendMessage({ db: ctx.db }, {
    conversationId, senderUserId: therapistUserId,
    text: JSON.stringify({ text: finalText, audioUrl }),
    type: 'voice', isAiAlter: true,
  });
  // 记 ai_alter_messages 日志（messageKind 标 'voice'），后续逻辑（亲密度/承诺账本等）照旧用 finalText
} else {
  // —— 文字分支：完全走现有 coalesceSegments 多段路径，零行为变化 ——
  const segments = coalesceSegments(splitIntoSegments(finalText));
  // ...现有 @1007-1034 循环原封不动...
}
```

**关键约束**：
- **语音永不阻塞**：`synthesizeWhisper` 任何异常 / 返 null → `audioUrl=null` → 自动落到文字分支。客户一定收到回复。
- **不分段**：语音是一条完整消息（真人不会连发 3 条语音）；文字才多段拟人。两套节奏不混。
- **日志/下游不变**：`ai_alter_messages`、亲密度、facts grounding 等下游仍以 `finalText` 为准，只是承载形式从 text 变 voice。
- **插话检测**：语音单条发送，无段间插话问题；文字分支保留现有段间插话停发逻辑。

### 3.3 第二条发送路径（主动触达 proactiveReachOut，ai_alter.ts ~1214-1233）

`maybeReachOutProactively`（主动触达）也走 sendMessage。**本期范围只做"回复客户"主路径（§3.2）**，主动触达语音化列为 P1（YAGNI——先验证被动回复的语音体验，再决定主动触达要不要也掺语音）。

## 4. 催复刻引导卡（P0）

- **对象**：`eleven_voice_id` 为空的技师（当前 66/67）。
- **位置**：技师端 `/t/me/ai-alter` 页，`<VoiceCloneCard/>` 区块上方加一张引导卡（仅未克隆时显示）。
- **文案方向**：「让分身用你的声音陪客户——更像真人，留得住人。30 秒录一段就行。」CTA 滚动/聚焦到下方 VoiceCloneCard。
- **数据**：复用 `GET /voice/me` 返回的 `cloned` 状态判断显隐，无新接口、无 schema 改动。
- **可选增强（P1）**：工作台首页（`/t/me`）对未克隆技师加一条同类提示；分身管制中心（M06b）显示"声音覆盖"状态。

## 5. 数据 / 接口改动

- **无 schema 迁移**：`messages.type='voice'` 已支持，`therapists.eleven_voice_id` 已存在。
- **无新后端接口**：复用 `synthesizeWhisper`、`sendMessage`、`GET /voice/me`。
- 新增：`decideAlterVoice()` 函数 + 2 个模块常量 + 引导卡组件（前端）。

---

## 6. 成本 / 可运营性

- 成本闸门：短句门把"长文本/卡片"挡在外，30% 抽签进一步限量。粗算每条语音 ≤ 60 字符 ElevenLabs 计费。
- P1：把 `VOICE_RATIO`、`VOICE_MAX_LEN` 搬 `app_config`（[[loverush_app_config_miniapp]] KV 表）后台可调 + kill switch，便于灰度/止损。P0 先用常量。

## 7. 测试

- **单测 `decideAlterVoice`**：短句门各分支（超长/含 URL/含卡片标记/正常）、真克隆门（有/无 eleven_voice_id）、30% 分布（注入 `rand` 断言比例）。
- **e2e（loverush_test 库）**：
  - Mei（有克隆）多轮回复 → 出现 `type='voice'` 消息且 content 含 `audioUrl`。
  - 无克隆技师 → 全 `text`。
  - 含链接 / 超长文本 → `text`（短句门拦截）。
  - `synthesizeWhisper` mock 返 null → 降级 `text`（不阻塞）。
- **本地无 key**：mock `synthesizeWhisper`（本地无 ELEVENLABS/OPENAI key 会真实失败），断言降级路径。参照 [[loverush_gift_alter_systemic_fix]] 的空 LLM-key fallback 测法。

## 9. 露馅红线护栏（生命线，[[feedback_ai_stealth]]）

- `cloneOnly:true`：声音必是技师本人克隆，永不用通用女声冒充。
- 客户端零 AI 标识：语音气泡与付费悄悄话同款，不暴露"AI 生成语音"。
- 失败静默降级文字，不出现"语音加载失败/合成失败"等暴露机器痕迹的提示。
